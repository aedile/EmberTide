# Phase 7: Visual Render Primitives (Host UI)

## Item 1: Implement Framebuffer Geometry Math

### User Story
As a UI engineer, I need a lightweight, heapless 200x200 pixel byte-array canvas that perfectly maps to the physical E-paper display orientation and byte-packing layout.

### Acceptance Criteria
- [ ] `components/presentation/include/fq_framebuffer.h` defines `fq_fb_t` with a static 5000-byte array (200x200 bits).
- [ ] Implements `fq_fb_put_pixel(ctx, x, y, color)`.
- [ ] Implements `fq_fb_clear(ctx, color)`.
- [ ] Implements `fq_fb_draw_line(ctx, x1, y1, x2, y2, color)` using pure Bresenham's algorithm.

### Negative Test Requirements (from spec-challenger)
- **Memory Corruption by Out-of-Bounds Plotting:** Call `fq_fb_put_pixel(-5, 205)`. Validate that the byte-array mapping logic explicitly drops the pixel rather than computing a negative array index and overwriting stack memory.
- **Diagonal Infinite Loop:** Verify Bresenham's line algorithm terminates safely even if `x1 == x2` and `y1 == y2`, or if coordinates are vastly outside the 0-199 bounding box.

### Implementation Steps
1. Create `fq_framebuffer.h/c` inside `components/presentation`.
2. Map `(x, y)` to the `buffer[(y * 25) + (x / 8)]` bit index.
3. Use strict bounds checking `if (x >= 200 || y >= 200) return;`.

### Test Expectations
- `test/visual/test_fb.c` draws an X from corners, outputs `output/fb_test.png`, visually verified by regression-checker agent.

### Files to Create/Modify
- `components/presentation/include/fq_framebuffer.h`
- `components/presentation/src/fq_framebuffer.c`
- `test/visual/test_fb.c`

### Commit Messages
- `feat: implement 5000-byte 1-bit packed framebuffer and primitives`

## Item 2: Implement Sprite Parser and Blitter

### User Story
As an artist, my 1-bit python-generated C header arrays need to be precisely blitted (copied) onto the framebuffer canvas at arbitrary `(X,Y)` coordinates, honoring transparent bounding rects.

### Acceptance Criteria
- [ ] `components/presentation/include/fq_sprite.h` defines `fq_blit_sprite(ctx, x, y, sprite_ptr, width, height)`.
- [ ] `fq_blit_sprite` correctly handles bitwise shifting when an X coordinate does not align perfectly with a byte boundary (e.g. `X=3`).
- [ ] Blitter clips sprites automatically if they exceed the right or bottom edges.

### Negative Test Requirements (from spec-challenger)
- **Partial Horizontal Clipping:** Drop a 32x32 sprite at `X=190, Y=0`. Assert that the blitter perfectly truncates the last 22 pixels off the right edge without wrapping them to the next row (Y=1) in the byte array.
- **Pointer Runoff:** Provide a `sprite_ptr` with dimensions `w=0, h=0`. Ensure the blitter exits instantly without executing a 0-loop or division by zero in bit-shift offsets.

### Implementation Steps
1. Write the byte-alignment shift logic in `fq_sprite.c`. 
2. Because E-paper is 1-bit, the blitter uses OR/AND masks instead of memcpy directly.
3. **[PRE-EXISTING]** Use the existing sprite structures located in `/include/fm_chars.h`, `fm_items.h`, `fm_icons.h`, and `fm_tiles.h` from our earlier rapid-prototyping phase. Move these files into `components/presentation/include/sprites/` during implementation.

### Test Expectations
- `test/visual/test_sprite.c` draws the Dark Knight sprite at offset X=5, Y=10 to guarantee unaligned bit shifting succeeds, outputting a PNG.

### Files to Create/Modify
- `components/presentation/include/fq_sprite.h`
- `components/presentation/src/fq_sprite.c`
- `test/visual/test_sprite.c`

### Commit Messages
- `feat: cross-boundary bitwise sprite blitter`

## Item 3: Implement Variable-Width Font Drawing

### User Story
As a UI designer, text must look polished with variable character advancement and precise line heights, using the metrics generated by the Python prep scripts.

### Acceptance Criteria
- [ ] `components/presentation/include/fq_text.h` defines `fq_draw_text(ctx, font, x, y, string)`.
- [ ] Implements the lookup logic from `font_metrics.json` (converted to C array).
- [ ] Properly advances X by `w + dx` and handles Y bounding offsets for hanging letters (like 'g' or 'y').

### Negative Test Requirements (from spec-challenger)
- **Non-Printable Characters:** Render the string `Hello\x01\x02World`. Assert the font parser ignores ASCII indices outside the printable `32-126` range rather than reading off the end of the `glyph_metrics` array.
- **Run-on String:** Pass a string without a null terminator, or a string of 10,000 "A"s. Ensure the text parser bounds execution to the edge of the 200x200 screen, breaking the loop before processing hidden characters forever.

### Implementation Steps
1. **[PRE-EXISTING]** Use the existing font bytecode arrays from `/include/fm_fonts.h` and the kerning data from `/tests/font_metrics.json`. Move/convert these into `components/presentation/include/fonts/`.
2. Write the string parsing loop in `fq_text.c`.

### Test Expectations
- `test/visual/test_text.c` renders "FiestaQuest!" with proportional kerning in the output PNG.

### Files to Create/Modify
- `components/presentation/include/fq_text.h`
- `components/presentation/src/fq_text.c`
- `test/visual/test_text.c`

### Commit Messages
- `feat: implement variable-width font primitive renderer`
